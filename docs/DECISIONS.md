# Lineage 决策记录

## 2026-11-10 · M0

- 使用现有 Git 根目录建立 pnpm 工作区。四个包先保留最小入口，由根配置统一构建。公开产品名暂为 Lineage，npm 包名、许可证和可选 LLM 汇总待所有者决定。
- 本机扫描优先验证 Zstandard。后续 Reader 需检测 Node 的解压能力并报告不支持的环境。同一会话 ID 的多文件记录需要按证据归组，不能把同 ID 简化成简单拼接。
- 优先调查 `token_usage_record` 与旧事件的重叠。分叉继承基线缺少可验证证据，后续用量质量应反映这一限制。
- 测试样本使用合成 ID、时间戳和数值。这样可以验证结构和关系，避免真实会话被反查。原文短字符串用等长占位，长字符串和数据 URI 用固定标记，动态键使用合成键。
- Claude Code 和 Windows/WSL 当前无本机证据。M1 的真实样本验收应明确报告各来源覆盖情况。M0 详细证据见 [本机会话格式核验](formats.generated.md)。

## 2026-11-11 · M1

- M1 只做 Codex 纵切。Claude Code Reader 顺延至有真实样本的 M1b。M2 到 M4 先覆盖 Codex 来源，Claude Code 可接收 Markdown 交接。
- 保留 Node 20。优先使用内置 zstd，较旧 Node 使用可选的 MIT 许可依赖 `fzstd@0.1.1`，通过流式接口逐块读取。两条路径在实测最大文件与合成超长行文件上均低于 300 MB。帧窗口超过 32 MiB 会报告失败，避免在解码前申请大块内存。缺少两种解码能力时，`doctor` 列出受影响文件和数量。[fzstd 上游说明](https://github.com/101arrowz/fzstd)
- 相同 ID 只使用一个 canonical。末条可识别时间戳优先，其次行数，仍并列按路径的字典序。其他文件保留为 alternates。重复 ID 的证据不足以建立 `split` 边。
- 用量按轮次对响应 ID 和用量签名去重，合并可比较且不重叠的旧式增量。若新式增量已与其累计快照对齐，且没有仅含旧式增量的轮次或更高的旧式累计值，则采用新式增量。节点展示去重后的文件内增量。能够逐计数项对齐末次快照的正基线单独记录，包含文件前基线本身不会降低质量。线程累计展示最后一条有效快照。去重冲突、来源差异、回落或证据不足时标为近似。`ls --json` 使用版本 2，缓存结构使用版本 3。
- fork 合计按子文件正增量签名检查父文件。有足够证据且无匹配时纳入文件内用量。有至少两个签名连续匹配且覆盖子文件所有匹配的开头区间时，合计扣除该区间内实际计入的增量。缺少足够证据的 fork 暂缓纳入，节点仍展示文件内用量。
- 脱敏保留通用变量名的保守匹配，新增五类凭证格式。三例误伤和自然语言密码限制见 [M1 脱敏边界](formats.generated.md#m1-脱敏边界)。
- `replacement_history` 存在文本。来源和适用性无法验证，因此接力包模板暂不采用。模板增加授权事项和证据缺口，均来自用户消息和结构化事件，按 `inferred` 标注。
- 缓存按路径、文件大小、mtime 和解析器版本隔离，缓存内容脱敏。私有诊断在临时目录运行。首次提交前已预扫 12 份文档及 9 份样本，未发现本机绝对路径、所有者身份、邮箱、私有仓库名或样本中的原文。首次提交仍待所有者单独确认。
- 作用域 npm 名、MIT 项目许可证和 V1 关闭 LLM 摘要是简报中的建议，发布决定待所有者确认。


## 2026-11-11 · M2

- 近似用量统计按现有 `usage.note` 分句。同一会话的同一原因计一次，各原因占比以近似会话为分母。一次真实扫描得到 333/862（38.63%）。
- 主线图按可验证的 Git 根目录归组。相似度使用 checkout 相对目录，关系证据要求同一 checkout 的同一条路径。这样，同仓库的多个 worktree 可以归入同一主线，各自的同名文件也能保持独立证据。
- 主线排序和组并入顺序按文档规则确定。无文件的同分支会话进入杂项，已验证的结构关系优先保留。overrides 按原始主线 ID 读取重命名和移动。
- shared-file 使用结构化文件修改证据，缓存升级到版本 4。fork 和 subagent 关系使用子会话的元数据字段。状态以扫描时点推断，重跑按同类型、同命令文本匹配，`idle` 可覆盖过期主线中的 `open` 或 `warn`。
- `lineage lanes --json` 使用版本 1，关系放在目标主线。用量复用 M1 的文件内聚合和 fork 扣除规则。黄金测试使用脱敏及合成输入和固定时间。

## 2026-11-11 · M3

- Viewer 使用同一组 TypeScript 纯布局函数，输出一个离线 HTML。内嵌数据仅保留页面字段，使用脱敏后的标题、有限长度的摘要、相对文件名和关系证据。示例模式全部使用合成数据。
- 已验证且父会话存在的子代理默认折叠。父星的自身用量与折叠后的合计分别展示，子会话的汇总沿用 M2 的 fork 纳入和扣除规则。有基线时另列线程累计。接力包仅显示 M4 占位。
- 同名主线使用首个会话的 UTC 日期。同日仍同名时，按主线 ID 追加编号。标题布局同时检查星体、标签和子代理徽标的边界。
- 一个本地仓库含 164 个会话，113 个子代理均找到父会话。折叠后 21 条主线共 51 个可见会话，每条主线 1–9 个。默认缩放下渲染 45 个图元，其中 4 个是星团。Chrome 检查未发现会话标签与徽标互相重叠。G2、G3 由所有者人工验收。
- 本机合成测试中，同一输入重复生成的 HTML 逐字节一致。500 会话生成耗时 4.2 ms、Chrome DOM 就绪 120.2 ms，默认星图。2000 会话生成耗时 10.9 ms、Chrome DOM 就绪 40.5 ms，默认列表。两个页面均无网络请求或 JavaScript 错误。HTML 扣除会话数据为 36,639 字节。Node 22.23.1 与 Node 20.17.0 的 `pnpm verify` 均通过。Node 22 通过 95 项，Node 20 通过 94 项，内置 zstd 专用测试跳过。

## 2026-11-12 · M4

- M3 星图明确披露标题、摘要、相对文件路径和主线名。截断的主线标签可通过悬浮或聚焦查看完整名称。短 ID 模式沿用从用户消息生成的主线名也被替换的规则，并省略内嵌接力包。更彻底的分享模式留到 M7。
- 接力包只读取 Codex 来源。Git 分支、HEAD、状态和 diff stat 在导出时读取，未能读取的字段在包内说明。测试和构建事实只采用结构化 CommandExecution 的退出码与输出尾部。旧式推断退出码仍可用于既有会话行为。缓存升级至版本 5。
- 已授权、待确认、约束、待办和证据缺口为启发式条目。保留来源指针。助手问题和 TODO/FIXME 从保留的脱敏片段提取。合成黄金用例验证 Markdown 和 JSON 的体积上限、脱敏、裁剪与 Git 降级。未使用 compaction 摘要和模型。
- 本机离线未核实外部 agent-handoff 格式，M4 只提供原生格式。普通星图内嵌构建时生成的各主线接力包，页面预览可编辑，支持浏览器复制和手动复制降级。
- 一条真实主线的 Markdown 估算为 1,994 token。分支、HEAD 与现场复核一致。各节正文行数为核对现状 2、目标 6、当前状态 5、最近检查 10、已完成 5、约束 14、授权与待确认 16、待办 20、指针 1。真实输出仅在本地交付，Claude Code 和 Codex 的粘贴验收由所有者完成。
- Node 22.23.1 与 Node 20.17.0 的 pnpm verify 均通过。Node 22 通过 114 项，Node 20 通过 113 项，跳过内置 zstd 专用测试。离线 Chrome 核验覆盖主线标签、接力包目标切换、预览编辑和复制降级。

## 2026-11-12 · M6 · MCP 服务

- M5 顺延，M6 来源限 Codex。M4 小修限制启发式条目、使用双语历史警告和本地时区。目标消息内的约束与和目标互为子串的约束都去重。
- 采用官方 TypeScript SDK `@modelcontextprotocol/server@2.4.0`，锁定 `core@2.4.0` 和 `zod@4.6.7`。使用冻结锁文件和 `--ignore-scripts`，项目构建许可列表为空。
- 本机 Codex CLI 0.133.0 在 stdio 发送 `initialize` 并请求协议 2025-06-18。SDK 2.4.0 的 `serveStdio` 兼容该握手。同一入口用 2026-07-28 协议也完成了工具发现。
- MCP 提供四个只读工具。禁用磁盘缓存，使用固定历史警告、有限摘录和 token 上限。现场 Git 查询仅限引用。CLI 可导出完整工作树状态和测试输出。SDK 客户端测试覆盖握手、工具发现、调用、错误降级和 EOF。用本机 Codex 在临时配置中调用了四个工具，无模型请求。
- 同一真实主线的 CLI 接力包复测为 1,914 token，分支和 HEAD 与现场一致。真实报告单独存于本地。Skill、安装器和真实新会话验收留待后续。

### M6 · 1d、Skill 与安装器

- MCP 保留脱敏后的用户消息至 600 字、最终助手文本至 300 字，超出时标注。默认按服务启动仓库限域，只有显式启动开关可跨项目。越界 ID 和目录通过安全错误处理。
- 一次未缓存的真实状态请求耗时 18,447 ms。活跃文件更新会使整份快照失效，因此加上逐文件解析和 fork 证据复用。内存缓存以路径、大小和 mtime 核对会话及标题索引。连续 10 次测量的 P50/P95 为状态 195/313 ms、接力 493/608 ms、搜索 33/147 ms、会话 29/146 ms。冷启动分别为 15,784、16,514、16,161、15,607 ms。
- SDK 子进程测试从独立构建目录启动，跨包源码导入在构建时已解析。安装通过厂商 CLI 变更注册，带版本与摘要的标记用于保护自管 Skill。临时 HOME 使用本机 Codex 验证安装、重复安装、范围切换、卸载和冲突保护。Claude 无本机命令，仅验证预览。
- 同一真实主线 MCP 接力包（含固定首行）为 1,839 token。Node 22 通过 136 项。Node 20 通过 135 项，跳过内置 zstd 专用测试。临时安装后的新 Codex 进程发现了 Skill 和四个工具，未启动模型回合。真实安装和新会话人工验收等待所有者确认，默认范围为会话启动仓库。

### M6 · 1e 冷启动

- 默认 MCP 先读取首条会话元数据并按 M2 仓库身份限域。完整解析保留同 ID 候选和关系所需的父文件。无法判断的元数据回退到完整解析。合成等价性覆盖工作树、嵌套仓库、符号链接、重复 ID、外部父文件、异常和 Zstandard。
- 真实仓库基线冷启动 15.6–16.5 秒。仅预过滤为 4.58–5.34 秒，叠加预热为 4.42–5.05 秒。最终握手为 66–74 ms。代表性拆解读取 907 个头部并选出 173 个文件，头部阶段 279 ms，正文解析合计 3,920 ms（含 fork 重读），图计算 8 ms。3 秒目标尚未达到。跨项目仍全量扫描，实测 17.20–26.83 秒。CLI 磁盘缓存未接入。
- 5,000 个合成会话各含 81 行，200 个会话属于目标仓库。完整解析 200 个文件，工具冷启动 638–923 ms，连续 10 次的 P95 为 66–310 ms。
- 安装预览提示本机 Node 和脚本的绝对路径，以及跨项目首次扫描耗时。发布待办为提供稳定的可执行入口。真实安装配置本轮未改。
- 本轮接力验证限 Codex 对 Codex。Codex 历史交给 Claude Code 的场景尚未验证。Claude 分支依赖的 `claude mcp add` 参数和对 `~/.claude.json` 的直接读取均未经实测。
- Node 22 的 pnpm verify 通过 138 项，Node 20 通过 137 项并跳过内置 Zstandard 专用测试。

### 正式改名

- 从 Lineage 改名为 TLineage。产品、CLI、MCP、Skill 和本地路径使用新名。旧名保留在历史与改名记录中，包清单的 `lineage.repositoryName` 保留指定的元数据键。
- 旧数据目录 `~/.lineage` 不迁移。确认其中的旧缓存、地图和备份无需保留后，可手动删除。

### MCP 磁盘缓存与命名配置

- 包清单的命名配置迁至 `naming`，发布暂存包同步读取新键。以上改名历史保留原文。
- MCP 工具仍只读面向代理数据和用户仓库。磁盘写入仅用于 `~/.tlineage/cache/mcp` 的脱敏会话副本及其私有目录，目录 0700、文件 0600。路径或权限无法核验时回退。CLI 已有缓存仅供读取。
- 独立缓存容量 256 MiB，条目 7 天过期，写入时清理。缓存键包含脱敏规则指纹。`--no-cache` 跳过两类磁盘缓存，保留进程内复用。`cache status` 和 `cache clear` 仅管理 MCP 缓存。安装预热另行确认。

### MCP 缓存锁与批量写入

- 写锁记录 PID、时间与持有者。持锁进程退出或达到 60 秒时可接管。损坏锁可通过 `cache clear --force-unlock` 处理。
- MCP 扫描和安装器预热批量写入，每批统计一次目录占用。待写数据最多暂存 64 MiB，超过上限的条目留待后续扫描。
- `doctor` 与 `cache status` 提供本地诊断路径和修复建议。MCP 响应不附带这些诊断。
